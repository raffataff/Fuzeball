## Conventions
- Plain non-module scripts sharing one global scope: a top-level `const` is visible in later files and **a duplicate top-level name anywhere throws**. Never convert to import/export (breaks `file://`). Element ids are globals too (`#lgGoals` = `window.lgGoals`): never name a function after an id.
- Dense terse style, `'use strict'` per file, short names, packed statements; match the surrounding code. `config.js` is the exception: spaced, one-line comment per value.
- Comments: only section titles (`// --- reaction latency ---`) and one-line notes on a non-obvious line or on what a higher/lower value does. No paragraphs, change-log/diary text, post-mortems, or restating code. Trim comments to this rule in any function you touch.
- Globals (core.js): `$` = getElementById, `clamp`, `lerp`, `lerpAng`, `rand` (**not seeded**), `byTeam(v,t)` (a CONFIG switch given as [red, blue] for a duel), `shRep(src,anchor,repl,name)` = every `onBeforeCompile` chunk patch (warns by name when three moved the anchor; a plain `.replace` misses silently).
- When updating a function, rewrite the WHOLE function, then re-read it in context (owner pref).
- New tunables go in `CONFIG` (`js/config.js`), never inline. The aliases at its bottom (`F`, `BALL_R`, `KICK`, `AIC`, `SHOT`, `DIFFS`…) are derived: edit CONFIG. Check the object for a same-named key first: a duplicate key silently wins.
- Every optional module hangs off one nullable gate on `S` (`S.trn`, `S.trial`, `S.tut`, `S.photo`, `S.redit`, `S.lg`, `S.show`), tested only by that module + one-line hooks. A missing optional file must never break a match. Core, unguarded: `rng.js`, `shots.js`, `binds.js`, `padnav.js`.
- New cfg key → `CFG_PLAYER` (Steam Cloud) or `CFG_MACHINE`. New per-rod timestamp field → reset it in `resetRodRotation` (a stale stamp from the last match blocks until `S.time` catches up). A hard set of a ball's position outside physics → `syncBall(b)`.
- Concise, direct replies (owner pref).
- Mixed line endings (some `js/` files are CRLF): a multi-line find/replace written with `\n` silently matches nothing. Use Edit or splice by line index.
- Room notes go in the comment ABOVE `CONFIG.rooms`: the room editor's export drops comments inside entries and unknown keys (why `audioMix.reverb.rooms` and `CONFIG.atmos` live outside it).
- The tree usually holds the owner's uncommitted work: never stash, reset or switch branches to compare; export HEAD instead (below).

## Core systems
**Sim.** Fixed `1/CONFIG.sim.hz` (120, keep it) with render interpolation (`b.prev`/`b.cur`, rod `iPrevOff`/`iPrevAng`, angles via `lerpAng`). Adaptive substeps (`subTravel`, up to `subMax`, `PHYS_Q`); friction `exp(k·h)` per substep (substep-invariant); rods posed per substep. Spin/Magnus is a pure horizontal rotation (no energy): keep it. A slow frame runs up to `sim.maxSteps` steps, so per-step costs multiply when frames are slow. Physics is not the frame cost.

**Seeded randomness (`rng.js`).** Anything that changes an outcome draws from a named stream (`RNG.<tag>`, per-rod AI streams); cosmetics use `Math.random`. `S.seed` = live match seed; `S.seedNext` consumed once by `startMatchNow`; `rngSeed` clears cached streams (a retry must replay).

**Contact (`collideRod`, physics.js; two passes, change both).**
- Contact velocity = rotation (the swing, in full) + slide (`cvz` × `kick.slidePush`). `holdCfg(r)` = sticky contact (AI trap/dribble, the player's hold). `aimAssist` / `wallAssist` bend strikes (pure rotations; `aimAssist` reads `r.aimEv.best.tz`).
- Foot box: dead (`kick.rest`), gripping (`grip`), sweet spot, assist. Leg capsule (`physics.prad`): bouncy (`kick.capRest`, `capGrip`) where the box doesn't reach. Both sized to the drawn figurines; a swing inside its power window (`restPower`) and `holdCfg` bypass this.
- Side bounce (`kick.sideRest`, `sideTake` / `sideGive`): a ball rolling along the rod bounces off a man's ±z faces; tic-tac is built on it (a down man bounces it, a raised man lets it through, a raised-back man lets it under then pins it). Only the ball's own approach rebounds: taken out before the contact and given back after the grip, so neither `grip` nor the ball's mass eats it. The front touch stays dead; the player's hold fades it (`shots.hold.side`).
- Rear (`kick.rearDot`, `rearCarry`): a backward-normal contact damps the ball's z instead of dragging it with the slide, except on a posed rod (`r.pinPose`: the cushion needs it).
- Speed ceiling (`kick.cap`, `capSpeed`): the toe outruns a capped ball and re-hits it many times a swing; `cap.keep` keeps a near-exit-speed ball's arrival heading on those re-hits (else every off-centre kick leaves straight). `cap.pin`, `cap.charge`, `cap.snake`. `cap.on:false` is unplayable.
- Boost (`boostSwing(r)`): only a STRIKE (leg turning forward in a kick or `shotOn`, or a pad stick faster than `kick.boostSwingW`) gets `KICK.boostHitMult`.
- Rim (`tables.<id>.wallH`, `WALL_H` set in `applyTable`, `rimLand` / `rimSeg`): the physical wall is as tall as the drawn one; a ball over it (`b.outWall`) lands on a round cap and rolls off. The arena lip has no rim; the `C` overlay draws walls at `CONFIG.table.wallH`.

**The pin** (physics.js `pinUpdate` / `pinBallStep` / `pinRelease` / `footUnder` / `footBoxD`; `CONFIG.shots.pin`). The carry runs outside the contact solver on purpose (a boot pressed on a ball squirts it out). A ball is held when it touches the FOOT BOX from above with its centre under the sole, inside the back (`back..front`) or forward (`fwdBack..fwdFront`) window the leg's lean picks, slower than `capV` relative to the rod. Nothing moves leg or ball after a catch. `footAngle(rel)` (ai.js) = the pose that puts the foot on a ball's top; from rel ≈ −1.0 to +2.5 no pose can (shin/ankle first). One ball per rod (`r.pinB` ↔ `b.pinR`). Released by finesse up, any swing, the rod turning off it, a knock, a hard set, a side wall. `pinSwing()` = the pin shot curve (`shots.pin.swing`: slower than trapShot so the boot doesn't scoop it over the bar) or the pin pass (`shots.pin.pass`, no wind-up: a pull-back swings the boot through a deep ball). Ring and HUD plate both ask `shotPinBall(seat)`.

**AI (`ai.js`, `CONFIG.ai`; `catch` below = `ai.catch`).**
Per active rod: ball seen through a reaction-delay ring (`aiView`), align a man (hysteresis, deadzone, drifting error), pick an action (`r.act`): `lane`, `catch` (phases below, `r.catPh`), `retrieve`, `safeRaise`, `evade`, `dribble` (+pass), `recv`, `run`, kick. `ai.hands` rods per team move; human-held rods are forced active. Tallies `CAS` / `CAW` (catch), `BGS` (back guard, retrieve).
Lessons that keep coming back:
- Static vs swept reach: `inFootRange` is static; anything that ROTATES the rod needs `sweepClips` + the leg, or the boot drags the ball goalward. A leg turning forward from rest sweeps through a ball ahead and blasts it: take a ball ahead from above.
- The kick gate is a snapshot: aimed/slow swings re-check with `strikeOn` / `strikeProbe` (`strikeGate.lead` covers `trapShot` having no wind-up).
- A swing starts where the leg IS (`kickA0`): from a leg forward of its curve's first target it sets off BACKWARD, and swings are exempt from the back guard. `kickBack` refuses such a plain kick, its pass, and the dribble release.
- Back guard (`ai.backGuard`; `backLimit` / `slideBlocked` from `updateRods`) is the last word on AI back-lift and slide. Any boot contact hands the ball the boot's velocity; a lift is safe only with the man z-clear until the boot is over the ball. Exempt: kick swings, trap, dribble, pin, human rods, except a human leg coming back from the forward pin (`backLimit(...,own)`, `r.fwdOut`) and any drop from a forward pose to rest.
- Read the REAL ball (`best.real`) in a phase that follows a contact (side catch, thru, tap, retrieve after a lift via `retKnow`): the delayed view still shows the old state.
- Never extrapolate a held rod with `laneObs`'s `vz` over ~0.1 s (AI slide is bang-bang). `ttObs` reads `target + r.tgV`.
- `pinUpdate` runs at the start of the NEXT step after `aiUpdate`: a ball stopped dead in one step needs the pose kept a moment (`recv.rest`) or the action ends first.
- Exits go through `catchEnd` / `retrieveEnd` / `recvEnd` / `runEnd`. `clearRodAI` (seats.js) wipes AI state when a human takes a rod.

Actions:
- **Raise back** off (`ai.raiseBack`): a ball from behind never raises a rod (`raiseBehind`, `rodHoldRaise`), so receivers stay down; safeRaise, retrieve and evade still raise.
- **Retrieve** (`ai.retrieve`, `retrieveStep`): a slow ball behind the rod: step aside, raise, settle over it, lower to `footAngle`, pin, `pinPlay`.
- **Catch** (`catchPick` / `catchStep` / `pinPlay`): pins with the player's pin. Phases: front, behind, side, meet, fetch, ahead, tap, hit, tictac, flift, hold, thru.
  **Timings by difficulty**: `catchT(r,k)` reads `catch.byDiff.<diff>.settleT` / `holdT` over `catch.settleT` / `holdT` (pro 0.15 / 0.8, legend 0.1 / 0.6); both take [red, blue].
  **`pinPlay` order**: open shot (`lineClear`; non-ATT rows `fwdClr`) → tic-tac (`tictac.first`) → carry (`pinCarryEval` / `pinTarget`) / tap → pass (`passPick`, `catch.open`, `carryFirst`) → past `holdT` the hold is worked (`catch.late`: the pull and the tic-tac whatever their draws, the tic-tac past its time-out cooldown; no still shot: `late.shot` brings back the old shot through any lane past `lanes.clear`, which a closing man blocked; `CAS.laneLate`). `hdSoak` (hold-soak.js): where held-ball time goes and what each pin play does. Lanes are judged with the opposing rows where they will be (`laneObs` / `fwdClr`).
  **Push** (`catch.push`): a shot fired while sliding keeps `carryOut` of the slide; `pinAim` puts the aim point on the judged line (else the assist bends pin shots to the middle). **Pull** (`push.play`; `puStep` / `pushBurst`, `r.puPh` sell|burst|stop; ATT): sell wide, burst back toward the middle, fire when the line reaches the near `post`, clear of men by `clear` (by role: a MID's line crosses field rows, so 0). `use` (by difficulty, a number or by role, [red, blue]) is ATT 1 at pro / legend (drew level in duels; a MID at 1 lost at legend). **Forward pull** (`play.fwd` roles, ATT): a forward hold the snake shoots (~2/3 of ATT holds are forward) plays it too, fired as the snake on the snake's line (`SN.drift` / `SN.k`) at `fwdMinV` or faster; ~1 a match at pro, drew level in duels at pro and legend. ~60% of pulls stop unfired, most with a man predicted inside the near-post line (`clear` -4 lost a little). hdSoak misses snakes (the pin lets go before the swing).
- **Side catch** (`catch.side`; `sidePick` / `sideStep`): a ball rolling along the row: men up, the pose drops `dropT` before it arrives; the rod runs with a quick ball (`cushion*`). Never start the pose early for a quick ball (breaks taps). `sideAngle(rel)` (the tic-tac tilt / let-through pose) must clear the real foot box (`footBoxD`, `boxGap`) or it stops every let-through dead.
- **Tap, the roll** (`catch.tap`; `tapEval` / `tapStart` / `tapStep` / `tapSide`): a stuck pin carries the ball along the row and lets go for the neighbour's side catch (`catPh` tap→side→hold). `tapSide` must NOT drop the pose in the release frame (the boot swings through the ball).
- **Tap back** (`tap.back`; `backEval` / `backStep`): DEF/MID; the sender's men go down with the boot square to the ball (an upright boot's corner knocks it backward) and slide in.
- **Meet** (`catch.meet`; `meetStep`): a slow ball along the row nobody will roll into: the nearest man AHEAD of it closes on it (a chaser pushes it).
- **Fetch / ahead** (`catch.fetch`; `fetchStep` / `aheadStep`): a slow loose ball ahead with no shot: clear → up → over → down onto its top → forward hold.
- **Under** (`catch.under`; `underStep`, `r.unPh`): a slow ball under a forward leg that the pin missed (the receive pose stops passes where the forward pin can't hold them): the leg goes up and fetch takes it, or the man steps off its line and lets go. Picked before every other catch.
- **Hit** (`catch.hit`; `hitAngle` / `hitStep`, `r.hPh`): the foot's ±z face knocks the ball to the neighbour. The foot must be still at contact (`tolW`, `tolA`) or it hands the ball x speed.
- **Tic-tac** (`catch.tictac`; `ttPick` `ttStart` `ttStep` `ttStrike` `ttCatch` `ttObs` `ttTouchU`; `r.ttPh` bounce|strike|thru): the default play for a held ball on every row (`byRole`: MID slower). Two neighbouring men, feet squared (`hitAngle`); the face the ball rolls to slides into it (`pace`, `lunge`); soft touches (`soft`; `ttTouchU`: exit ≈ 0.58 × slide + `kick.sideRest` × the ball's speed, so a still face is the softest). Strike: the leg tilts to `sideAngle`, a `trapShot` swing; the slide commits once the lane clears by `prep` (`guard` for defenders). Let-through (`thru`, ATT/MID; a MID's always follows a soft touch). Every end that keeps the ball is `ttCatch`.
- **Kick heading**: `kickLaunch` predicts the first boot contact (swing curve, ball motion, the slide the rod will hold); `kickLine` projects the heading with aim assist. Pin passes and tic-tac strikes commit their planned slide through contact.
- **Lane gate** (`ai.lanes`; `laneShut`): no AI kick leaves into an opposing man, judged from the REAL ball. A shut plain kick becomes a lane-checked pass or no swing (the man stays down and blocks). Exempt: the dead-ball push (`r.force`) and the keeper. Passes keep `dribble.pass.minClear`. `lanes-harness`, `pkSoak`. **Lane look** (`ai.laneLook`, shipped off; `rowLook`): a row read where it is heading (target, top speed, flight + wind-up) and widened by `reach` of what it can cover. laneObs's `offset + vz × flight` misses by ~2.6 u (the row moves ~2.7 u a shot) and its open lanes were touched by that row 47% of the time, but no forecast scored more in duels: the defence can reach almost any lane in a shot's flight, and a reachable shot still scores sometimes (`llSoak` + `tools/lanelook-models.js`). **Power** (`ai.power`, shipped off; `aiPowM`): a plain kick swings the player's power shot (`shotBlend`, `shotArm`); 118 → 134 u/s at 0.7 changed no field-block rate and lost or drew every duel, with or without the power swing's aim / stamina costs. AI swings already leave ~1 step after the decision.
- **Kick worth** (`ai.kickWorth`, shipped off; `kickWorth`, tallies `KWS`): a plain kick waits (`wait` by difficulty) unless the lane is `open`, the ball is fast, a threat or contested. On, it cuts plain kicks ~20% and goals ~15%: the catch layer can't keep the held balls. `kickworth-harness`, `pkSoak`.
- **Pass steer / run-up** (`catch.steer`, `steer.free`; `steerHeading`, `runStep`, `r.act==='run'`): a pin pass commits a slide toward the mate; a slow ball a few units ahead gets a run-up pass. **Shot run-up** (`steer.shot`, shipped off; `shotRunStart`, `r.rnShot`): the ATT walks the boot's corner across a slow ball and fires once the predicted shot clears; it lost its duels (the defence moves during the run). A plain kick's heading comes from where the boot meets the ball, not the slide (~0.001 rad per u/s; ~0.2 rad at most from a ball 3 ahead, ~0.45 at 2.5 or 4.5).
- **Receive** (`catch.recv`; `recvArm` (from `kickRod`) / `recvStep` / `reseat`): the target rod holds the forward pin pose (`recv.angle`, the same number as the player's) on the ball's line. **Ready** (`recv.ready`, `recvReady`, `r.rvReady`): mates ahead stand posed when a holder looks at passing or has the ball; a pin pass waits for its receiver. From under a forward leg no swing is possible (the wind-up sweeps through the ball): the ATT snakes, else `reseat` via the forward lift (`fliftStart`). Keeper's kick (`dribble.pass.gk`, `gkHold`): passes to the DEF ahead.
- **AI snake** (`catch.snake`; `snakeHold` / `snakeFire`): a shot from a forward hold is the player's snake, for its `roles`, `use` by difficulty; slide carried through.
- **Dead-ball push** (`ai.force`; `deadLeft(b)` in powerups.js, also on the `C` overlay): per rod (`r.force`, never ball-wide): square up and kick/pass now before the whistle.
- **Keeper safe-raise** (`safeRaise.gkAlways`, `srGoingIn`): the keeper lifts for a ball crossing its front/heel, not for a shot going in. −1.0 blocks the pocket, −1.3 is over it.
- **Goal cover** (`ai.cover`; `coverZ` `coverFit` `coverReach`; `cover.track`, `gkFollow`): GK + DEF body shadows on the goal line fitted for the smallest, evenest gaps. `cover.on:false` = the old line-block.
- **Strike reaction** (`ai.jolt`, `DIFFS.*.rt` 0.25 / 0.20 / 0.16 × `stReact`; `ballRecord` marks a rod contact that changes the ball's speed past `jolt.v` (`b.tchT` stamped in collideRod's two sites), `aiView` shows the other team the ball carrying on as it was for `joltRT(r)`): a shot is faster than any human reaction, so the defence can no longer react to it. AI-vs-AI goals per 2-min match went from 0.54 to 2.34 at pro and from 0.78 to 2.01 at legend. Many catch phases read `best.real` and skip it.
- **Holder read** (`ai.read`; `readTick` / `readHolder` / `readFit` / `readLearn`, state `RD[team]`, tallies `RDS`): against a ball held by an opposing ATT/MID (seen through the keeper's view), the GK + DEF fit is solved over the shots the hold can become (strike points `moves` across the holding man's reach × aim points, weighted by priors and the match's learned aim / strike-side bins, `mem.use` by difficulty), every other row a fixed shadow; `coverZ` takes `readOff(r)`. In duels from both sides (144 matches each) the reading team concedes ~15% less (pro 0.92 vs 1.08, legend 0.99 vs 1.11). The **guess** (`guess.k`, a favoured strike point re-picked) is shipped off; the **bait** (`bait.p`: leave the favourite lane open, jump on the timer or the tell a reaction later) lost AI duels but the owner switched it on (0.3 / 0.2 / 0.1, rookie baits most). **Jostle** (`read.jostle`, ATT holds, `set` phase only): each fitted rod slides to a fresh spot within `amp` of its fit every `every` s (by difficulty), drawn by cover (softmax at `slack` over spots at least `step` from the last, the mate where it stands); it stops once the holder's swing is seen (`rd.swS`, a swing started `joltRT` ago), not on the read's tell (the AI holder trips that all the time); the fit's slide cost is taken from the un-jostled fit. AI duels: about level at legend, slightly worse at pro (the AI attacker reads our rods live with no delay, so a moving defence is no harder for it to read). None of these has been tried against a human. `on` takes [red, blue]; tallies `jT` / `jMv` / `jRev` (fitted rods' time, slide, turns against ATT holds). `read-harness`, `read-soak.js` (`rdCells`).
- **Rod view** (`ai.rodView`, shipped off; `rodRecord` each step, `rodSeen(r2,team)` = {offset, vz, target, tgV} as that team sees the rod): every AI read of an opposing row (`laneObsAt`, `rowLook`, so `fwdClr` and the lane gate, `ttObs`, `dribPressed`) sees it as it was rt × `k` ago, its slide carried on toward the target it had then; own rows live; `r.rvW` reset in `resetRodRotation`. Built so a moving defence (jostle, bait, a human's) can fool the AI. On (pro, 48 matches): plain kicks 14 -> 21 a match, 66% of its "open" plain kicks met an opponent (39% off), snakes 4 -> 8, goals +23%, dead balls up; the late-reading team lost every duel (pro and legend, both sides), and the jostle still didn't win duels with both sides reading late. Harnesses that slice the lane code stub `rodSeen` (live). `read-harness`, `rdCells` cells `rvR` / `rvB`.
- **Calm** (`ai.calm`; `calmK` / `calmGo`): a rod far from play smooths its wanted slide and stands its ground. `calm-harness`, `fgSoak`.
- **Slide** (`ai.slide`, rods.js `aiSlide`; pro and legend only, `diffs`): an AI rod brakes to stop on its target (`sqrt(2·a·d)`) and feeds the target's own motion forward. A target within one step that moved with the rod (`target = offset + v·dt`, the cushion / runs / lunges / `r.target=r.offset`) is a speed command, driven as given (`cmdTol`); a strike slide (`r.catSw`) is never braked. The ATT with the ball in `strike.rel` keeps the old overshooting run: the overshoot is what puts the boot's corner off the ball, and that corner is a plain kick's heading (braking the ATT costs its goals; `strikeSlide` cannot rebuild it, the swing lands too soon). Braking everyone else: a 3 u move settles in 0.19 s (was 0.63, 5-8 reversals); a braking team outscores an old one ~0.39:0.24 a match, AI-vs-AI goals halve (defence gains more). `brake` takes [red, blue] for duels (`pkSoak` `goalsTeam`): judge slide / attack changes by duels, not both-sides goal totals. `slide-harness`, `slide-probe.js`.

**Difficulty & stats.** `DIFFS` (rookie/pro/legend) per team (`cfg.diffRed` / `diffBlue`; `teamDiff` reads a trial's or league's pin first). Seven rod stats (`CONFIG.stats`, base 5 = neutral): speed, hit, aim, grip, reaction, stamina, iq. Stamina = the match clock + each rod's exertion (`stats.kickFat`: every `kickRod` swing, and a pad stick swing past `stickW` via `stExertStick`), bled at `recover`. It slows slide, reaction, AI aim and iq, never the kick. `stSoak`, `stamina-harness`.

**Dead ball.** Displacement-based (a ball boxed into a small area for `stallT`), faster in dead zones (corner pockets, goal roofs, between-row lanes). Re-drops land in the third the ball died in (`redropZone`, `S.serveAt`). Goal kickoff (`kickoffSpot` in balls.js, `CONFIG.serve.kick`): ball at rest in front of the conceding team's MID (`S.kickTeam`, set in `onGoal`; −1 = the opening drop).

**Moments & match stats.** `moments.js`: saves (GK only), woodwork, goal types (curler, screamer, snake…), notices, time-pinch, crowd reactions. **Never add a "lands short" rejection to `momOnTarget`** (it kills every save). `matchstats.js` keeps its own ledger, independent of the moments toggle; `msStroke` counts a human's forward-pin stroke as a swing touch.

## Controls
**Seats (`seats.js`).** `S.seats[]` = every human: team, claimed devices (`kbd`, `mouse`, `padN`, `pad*` = first pad), held rod. A solo seat holds keyboard + mouse + pad. Resolve device → seat → rod: `seatForDev`, `seatRod`, `seatOf(r)`, `isUserRod(r)`. `userRod()` / `S.userTeam` = the PRIMARY seat only. Up to 4 a side.

**Auto rod-switch zones** (`CONFIG.control.zones`; `zonePick`, used by `userControlUpdate` and `autoHoldRod`): two painted 48×28 maps (`G D M A .`, from red's end; blue reads them turned round): `def` while the other team has the ball, else `att`; `.` falls back to nearest in x; `hyst` keeps the held rod. Painter: `C` overlay → AI DEBUG → Rod Zones (COPY gives the config block).

**Bindings (`binds.js`, `CONFIG.binds`, `cfg.keyBinds`).** Every rod action is a binding (key code, `Mouse0..4`, `WheelUp/Down`); the binding's device decides the seat. Defaults: arrows/W-S or mouse slide; ←/→, A/D, Q/E or wheel switch rod; Space/LMB kick; L-Shift/RMB raise; R-Shift power; R-Ctrl finesse; 1-4, B guide, V camera, R retry trial, S save clip, M next music track. Reserved: Esc, F1, F2, F3, F4, F9, dev keys C/L/F. In a match every bound key is `preventDefault`ed; Alt and F10 are swallowed on down and up (they steal focus and drop pointer lock). `modSync` reconciles modifiers from every event (Windows drops one Shift's keyup while the other is held). Ctrl+W/T/N must be blocked by the Electron shell.
Pointer lock (`mouseLockWant` / `mouseLockTick`): wanted through play/count/goal/replay while a seat holds the mouse; a refusal latches `mlRef`; `body.mlHide` hides the cursor regardless. Pause, win, menus, cards, the training panel and the zone painter want the cursor.

**Shot verbs (`shots.js`, `CONFIG.shots`; `shots.on:false` = pre-shots controls).** One step per seat per frame (`shotSeatsUpdate`, after `gamepadUpdate`) on the merge of every device's record. Physics reads only `r.shotOn` / `shotPow` / `shotCtl`, spent by the first contact.
- **Axis** = power − finesse (RT − LT, R-Shift − R-Ctrl), −1..1, blends the swing curve; both held cancels.
- **Charge** (`charge.needRaise`): power + a pull-back (KBM power + raise; pad RT + X or RT + right stick back) winds up; only a kick fires it; letting go cancels. Power is the ARC (`kickA0` → strikeA over a fixed window). Don't stack restitution multipliers.
- **Back pin** (finesse + raise; pad LT + X, or the right stick in `pin.band`): poses at `pin.angle`; gated on finesse DOWN (`I.fin`), not the eased grip. Kick from it (`pin.press`, `press.shoot`): on a rod in `press.roles` kick = the pin pass at once (`shotPinPass`, aimed down the slide's line at the next own rod, which `recvArm` readies), power + kick = the pin shot (`shotPinFire`; `shotPowHeld`: the power key or pad RT past `powAt`; power on a pinned ball never winds up). Other rods shoot on any kick. `press.shoot:'double'` = the old way (one press waits `dbl` for a second, the shot). A pin keeps the last four steps' slide (`pinRelease`, `r.vzH`): kick straight off a slide = push/pull.
- **Forward pin** (finesse + kick; pad LT + A; `pin.fwd`; `shotPinFwdPress` / `shotFwdAngle` / `shotFwdHold`): poses `r.pinPose` + `r.pinFwd`; the angle is the AI's fetch geometry for where the man stands. A tapped kick (under `hop.tap`) is the stroke (the pass); held, it pins (the man hops off a ball the rise would touch and comes back over it). **Letting go is the dangerous half**: with `r.fwdOut` set, a slow ball just ahead sends the leg UP and forward until the man is clear; anything else comes back through `backLimit(...,r.fwdOut)`. Kick still held as finesse goes keeps the men up (`fwd.raise`, `r.fwdRz`).
- **Pin assist** (`pin.assist`, `shots.square`; `shotPinAim` / `shotSettle` / `shotStickPin` / `shotSquare` / `shotPinInput`): the leg goes up over a slow ball and down onto it once over it, never lowered through a ball it is under; a still slide draws the man onto the ball's z (`settle`); finesse alone squares the foot to a low ball beside a man. Unlatched (`pin.latch:false`): the back pose lasts while raise is held, the forward one while kick is.
- **Receive** (`pin.assist.recv`; `shotFwdRecv` / `shotRecvAsk`, `r.fwdR`): finesse + kick held poses the forward leg at `ai.catch.recv.angle` (one number for player and AI) for a low ball from behind, drawing the man onto its line; while a seat asks, its AI rods ahead stand ready. No HUD cue.
- **Roll re-pin** (`pin.assist.roll`; `shotRollAngle`, `r.pinRl`): a ball rolling along the row to a man poses the foot at its arrival depth, back or forward, caught up to `roll.capV`.
- **Snake** (`shots.snake`; `shotSnakeFire`, rods.js `snakeStep`, physics.js `snakeLoft`): ball held under the forward leg, finesse held, power + kick (`press.shoot:'double'`: a second kick within `dbl`) → the man spins over the top and through. `r.angle` stays within ±π: the turn is one wrap with `prevAngle` moved too; render/replay use `lerpAng`. A foot too fast at the ball scoops it; `powTo` must stay past `spin`. Not in the controller reference (a row there scrolls the panel at 1280×800) or the tutorial.

**Pad in a match (`gamepadUpdate`).** Left stick / D-pad slide, right stick = absolute rod angle, A kick, X raise, LB/RB switch, B guide, Y camera, Start pause, View retries a trial, PS touchpad next track. A pad has no kick hold (A swings and drops). On a pinned ball X / B pass and shoot (`cfg.padPinBtns` 'sq' / 'ci' swaps them / 'off'; `shotPinBtns`), and B is not the guide while it is. Total Control (`cfg.padControlMode`): triggers are slide-speed modifiers + a swerve line on the free right-stick axis. Not rebindable (Steam Input). `tools/pad-harness.js`.
- **Slide** (`slideBy`): a full press = the rod's own top speed (`rodSlideMax`, rods.js: stamina, frost, a carried ball), the target never more than `control.slideLead` ahead, so the man stops when the hand does.
- **Right stick after a switch** (`control.handover.stick`, `seatStickSwitch`): its angle carries onto the new rod, a backward turn through `backLimit(...,own)`; off = disarmed (`padAngleArm`) until it re-centres.
- **Stick receive** (`pin.assist.recv.stick`, `shotStickPin`): finesse + the stick pushed forward with a ball coming from behind = the button receive.
- **LT** (`shotPadRead`): squeezed to the pass depth (`pass.modAt`) it latches full until let back past `hold.from`; an A pressed while LT is still travelling waits up to `pass.chord` for it (`shotChordWait`).

**Menus on a pad (`padnav.js`).** Spatial nav off the live DOM (default focus in `NAV_SCREENS`; screens may add `onPad` / `onPadStick`). The cursor is a `.navFocus` class, never DOM focus. B presses the screen's `.backBtn`, LB/RB switch tabs, Start = the primary action. ◀▶ move between PANELS, never change a value, stop at the edge. Every `<select>` on a `.screen` is a ◀ VALUE ▶ selector (`vsel.js` wraps it; the select stays the truth): A opens, ◀▶ cycle, A keeps, B restores; bare selects (dev panels) use `#navDrop`. **`data-vsel="list"` = a pick list** for any select whose change loads something (Kick Off Table / Skin / Pitch / Location; give it to future venue pickers): A or a click opens `#navDrop` (`navDropOpen`), one load per pick. An open value owns A/B. A press the menu used is eaten. Prompts come from `PAD_GLYPH` (Xbox/PS/Switch) and follow `inputKind()`.

## UI
- **Screens (`screens.js`)**: every navigable screen is one `SCREENS` entry (`showScreen` / `backScreen` / `hideScreens`); overlays (pause, win, dialogs) aren't. A screen with live state tears it down in its `onHide`. `#menu` IS Kick Off; `#home` is the landing page. A match returns to `S.fromScreen`.
- **Layout editor (`layout.js`)**: a screen gets draggable panels from a `lay` block in its `SCREENS` entry. Saved in `cfg.layouts` v2 (x/w fractions of canvas width, y/h px; `layStore` / `layPx`). Presets: built-ins in `CONFIG.layoutEditor.presets` (author with `layExport(key)`), the player's in `cfg.layoutPresets`.
- **HUD (`hud.js`)**: one `pointer-events:none` canvas that polls `S`; callers push events only: `banner` (tier 1), `notice` (2), `toast` (3), `hudHint(kbm,pad)`, `hudCount`, replay state. Hint markup: `[KEY]` keycap, `[LMB]`/`[MOUSE]`, `{A}` pad button, `·` separator, `\n`. Keyboard hints come from the bindings (`bindHintRods`, `bindCap`); each mode's hint is one builder returning [kbm lines, pad lines] (`matchHint` in flow.js, `trainingHint`, `trialHint`); `hintRefresh` re-sends only if changed.
- **Plates (styles.css, FEDERATION PLATES)**: buttons, tabs, menu items, chips = two clipped pseudo-layers: a rectangle with top-left and bottom-right corners cut at 45°. Panel caption tabs (`.panel>h3`, `.slotNo`) cut only bottom-right. **Nothing slanted** (owner: 20° parallelograms read as generic AI design); the only exception is the HUD scoreboard. Style a plate ONLY through `--pl` (fill), `--pr` (rim), `--pc` (cut), `--pk` (text); a new plate control joins the `:is()` lists. Never put `background`/`border`/`clip-path` on the element (clip-path clips the pad focus). `.btn` = gold primary, `.btn.ghost` = blue secondary.
- **Type**: `--font-display` / `--font-ui` = **FuzeClip** (already leaned 20° and declared normal + italic from one file, so `font-style:italic` adds no slant; Soccer League is the fallback for missing glyphs: no `ß Æ Œ`, lowercase aliased to capitals); `--font-body` Exo 2 600 for sentences. Sized for 1280×800 (Steam Deck) + sofa: nothing in a menu under 11px. **No menu screen may scroll at 1280×800**: run `node tools/menu-shots.js [names]` after adding to one. A `.lgSide` column's panels need `flex:0 0 auto` (the generic 380px basis is a HEIGHT in a column).
- **Style rules**: no emoji in UI copy. SoccerLeague / Russo One ship ONE weight: never bold. Gold marks focus, selection and trophies only. A CSS class not in the markup fails silently: check new selectors against what the code emits. Flex/grid parents stop margin collapsing.
- **Motion**: a screen change arrives behind one left-to-right wipe (`.scrIn`, from `showScreen`); the menu camera eases to a per-screen shot (`CONFIG.camera.menuShots`) with no idle drift (keeps the render throttle settled).

The win screen is a full-time board (`#winBoard`, filled in `endMatch`).

## Modes
- **Kick Off** (`roster.js`): per-player seat cards, press-to-join, 4-a-side local co-op.
- **League + Champions Cup** (`league.js`): the player is team 0; builds and upgrade parts. Rules (`lgGoalCap` / `lgMins`) belong to the save; the cup uses the league's. The venue belongs to the session (`lgVenueEnter` / `lgVenueExit`). The cup is a seeded tree.
- **Training** (`training.js`, `S.trn`): the sandbox.
- **Skill Trials + daily** (`trials.js`, `S.trial`): training with a rulebook. The clock is sim time from your side's first TOUCH (`trialGo` / `trialTouch`, hooked at collideRod's two contact sites and pinUpdate's catch; never `S.stats.kicks`, which misses stick swings, strokes, taps). Retry re-seeds from `S.seed` onto the same table (`trialHome`). `S.matchTime` held at 0 (no stamina ramp). Spawns must clear the resting foot box and stay in reach (the harness checks from live CONFIG). The daily is a pure function of the date.
  **Drills** (`goal.kind 'drill'`, `CONFIG.trials.drill`, `TRL.dr`): nine per rod, browsed in sets (`CONFIG.trials.sets`). Facts behind them: a ball in a man's own lane can't be back-pinned (placed balls start beside a man); the assist pulls long pin shots to the centre; DEF / MID shoot from the back pin with two kicks, so their bots kick twice (`shotTwice`). Medals come from `trSeeds` bot medians.
- **Tutorial** (`tutorial.js`, `S.tut`, armed from `trainingEnter`): two courses (`tutList`): basics (`CONFIG.tutorial.lessons`) and Advanced Moves (`.advanced`). Offered once before the first Kick Off / League (`tutOffer`, `cfg.tutSeen`); only the basics set `cfg.tutDone`. Text = the live bindings (`tutKey`), written only on change (`tutHudSync`). Balls sit on the near side (the panel covers the far third). Gotchas: letting go of finesse and raise together over a back-pinned ball swings the boot through it ("keep raise held"); a kick held past `hop.tap` in the receive lesson pins on the passer.
- **Replays** (`replay.js`): ring buffer re-posed from footage, with sound and saveable clips; the match winner gets one.
- **Photo mode** (F1, `photo.js`): stills, clips, offline turntables.
- **Room editor** (F2, `roomedit.js`, `CONFIG.debug.roomEditor`): exports paste-ready `CONFIG.rooms` blocks.
- **Figurine Sizer** (F4 in the menus, `figedit.js`, `CONFIG.debug.figEditor`): edits `playerModel.models[].scale` / `rodY` live, COPY gives `{id, scale, rodY}` lines. A man's root y = `manY(t)` / `figY(am)` (config.js): `rodY` (GLB units up from the origin) lands on the rod and `scale` grows about it. The physics foot box does not follow: a figurine's feet belong on the green line (FIT FEET).
